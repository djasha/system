## Prompt

Implement per-product theming for a token-based design system: core tokens define surfaces, ink, and a default accent layer; each bundle theme is a body class (e.g. .bundle-openclaw, .bundle-hermes) that overrides ONLY the accent-layer variables — --accent, --accent-text, --accent-deep, --accent-soft, --btn-bg, --btn-edge — plus their [data-theme="dark"] counterparts. Components are never forked per bundle. Themes also gate bundle-specific mascots: .bundle-openclaw shows .mascot-lobby, every other context hides it.

## Usage

- Apply with `<body class="bundle-openclaw">` (lobster red, Lobby visible) or `<body class="bundle-hermes">` (messenger amber, winged bolt, no lobster).
- New bundle = copy `themes/_template.css` to `themes/<bundle>.css`, fill six accent variables + the dark block, verify contrast. That is the entire per-product design step — built for a bundle-a-week cadence (see `src/autokit/DESIGN.md` §7).
- Shipped themes: `openclaw.css`, `hermes.css`, `botbento.css` (bento teal — AutokitBotbentoFunnel), `seller.css` (market copper — AutokitSellerBoxFunnel; replaces the sketched amber that collided with Hermes), `content.css` (creator berry — AutokitContentBoxFunnel), `vault.css` (vault plum — AutokitVaultFunnel). Core tokens at `src/autokit/tokens.css`.

## Do / Don't

- **Do** keep theme files tiny — if a theme needs to touch surfaces or ink, the core tokens are wrong.
- **Do** re-check WCAG contrast for each theme's `-text` variants in both light and dark.
- **Don't** fork components per bundle — that's the rule the whole system exists to enforce.
- **Don't** show Lobby outside `.bundle-openclaw` — the theme CSS is the enforcement point.
